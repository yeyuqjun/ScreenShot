# 架构与协议

前端为 React + TypeScript 网页，由 Electron 承载。截屏、贴图、剪贴板、全局快捷键和凭据存储由桌面主进程提供；网页通过受限 IPC 调用，不能任意访问文件系统或执行命令。

后端为独立的 Rust / Axum HTTPS 服务，使用 SQLite。它不采集屏幕，也不接收截图，只保存用户、会话和加密配置。默认监听 `127.0.0.1:8899`，可部署到 Windows 或 Linux。

## 模块

| 路径                       | 内容                                           |
| -------------------------- | ---------------------------------------------- |
| `src/ui`                   | 网页界面、设置、选区、标注、贴图及录制控制     |
| `src/desktop`              | 主进程、受限 IPC、捕获、GIF 编码、加密同步     |
| `src/shared/defaults.json` | 默认设置                                       |
| `src/server`               | Rust HTTPS 服务及 Windows 控件几何识别辅助程序 |
| `tests`                    | 图像拼接、加密、GIF、API / AI 请求测试         |
| `scripts`                  | 启动、构建、打包及 HTTPS 联调                  |

## 配置保护

1. 通信始终使用 TLS，验证证书链和主机名。自签名服务需导入 `server.crt` 公钥证书，不关闭校验。
2. 服务端密码使用 Argon2id 哈希及独立随机盐。
3. 客户端根据密码及账号专属 32 字节盐，通过 scrypt（N=16384、r=8、p=1）派生 32 字节配置密钥。
4. 配置以 AES-256-GCM 加密：12 字节随机 nonce、16 字节认证标签、附加认证数据 `snapdock-config-v1`。服务端只接收密文。
5. 本机设置、接口密钥、会话令牌和派生密钥通过 Electron safeStorage / Windows DPAPI 保存。登录密码不落盘。
6. 同步包含偏好、快捷键、OCR / 翻译接口及密钥；不包含截图、本机目录、开机启动、账号密码或服务连接参数。
7. 导出 JSON 不含接口密钥及凭据；导入时保留本机已有密钥。

会话令牌使用 32 字节随机数，数据库仅存 SHA-256 摘要。默认 168 小时有效，可在数据库修改。注销撤销当前会话；离线注销会清除本机凭据，界面会说明远端会话需等待过期。

## HTTPS API

业务错误返回 `{ "error": "说明" }`。响应带 `Cache-Control: no-store`，请求体最多 256 KiB、密文最多 128 KiB。认证按连接来源 IP 限流，不信任客户端转发 IP。

| 方法 / 路径                  | 用途                                                                |
| ---------------------------- | ------------------------------------------------------------------- |
| `GET /health`                | 存活检查                                                            |
| `GET /api/v1/meta`           | 版本及注册开关                                                      |
| `POST /api/v1/auth/register` | `{username,password}`；注册并创建会话                               |
| `POST /api/v1/auth/login`    | `{username,password}`；返回 token、expires_at、username、vault_salt |
| `POST /api/v1/auth/logout`   | 撤销 Bearer 会话                                                    |
| `GET /api/v1/config`         | 当前用户密文；无配置时 revision=0                                   |
| `PUT /api/v1/config`         | `{expected_revision,nonce,ciphertext}`                              |

配置接口按会话确定用户，不接受用户 ID。上传在 SQLite 事务中比较版本，成功后 revision 加一；不匹配返回 HTTP 409，不覆盖现有配置。

## 捕获

按显示器冻结画面，逻辑选区根据实际图像尺寸转换为像素坐标。窗口边界使用 Win32；控件几何优先由独立 Rust UI Automation 进程获取，失败时回退原生子窗口。辅助进程有超时，不读取目标控件文字。

选区和编辑器共用 `AnnotationToolbar`、`AnnotationCanvas`、`useAnnotations` 与画布渲染逻辑。`Bubble` 负责气泡定位、屏幕边界和关闭交互，多选项使用原生下拉框。一级菜单点击后选择该组第一项；各工具参数保存在 `settings.annotations`，通过主进程队列写入加密配置，包含在偏好同步及 JSON 导出中。

标注保存在独立图层，橡皮擦以 `destination-out` 擦除标注，再与原图合成，保留原图透明度。文本 / 水印有稳定元素 ID、坐标、字体和内容；按原图像素命中测试，在画布上方显示按显示比例缩放的输入框。点击别处提交，Esc 取消，文本修改可撤销。历史同时保存合成 PNG、`<id>.source.png` 原图与 `<id>.annotations.json` 标注记录，重新打开后可继续编辑；删除和历史清理会移除配套文件。导出的普通图片只包含合成结果。

选区工具栏通过 `capture.select` 传递选区、目标模式、操作、物理像素 PNG 和标注记录。主进程校验模式、操作、图像尺寸、标注数量及参数后，完成复制、保存、贴图或打开编辑器；录制 / 长截图使用当前选区，不带入静态标注。

选区、编辑器和贴图共用 `SaveDialog`。`save.defaults` 提供上次保存参数；`image.save` / `capture.select` 接收文件夹、文件名、格式和质量。主进程校验绝对路径、文件名及格式，编码真实 PNG / JPEG；JPEG 先将透明像素与白色合成，GIF 复制原始动画文件。新文件独占创建，已有文件通过系统对话框确认替换；选区在导出成功后关闭，导出失败或取消替换时可重试。路径、格式和质量保存在本机配置中。

长截图先在选区界面保留可调整的选框，选择自动 / 手动模式，点击开始才通过 `capture.select` 传入 `scrollMode`。运行时用原生中空窗口保留选区边框，窗口形状排除选区内部并穿透鼠标；控制栏优先放在选区外。边框及控制栏使用系统捕获排除，避免进入长图，完成、取消或失败后一起清理。

长截图固定采集选区像素；只有自动模式会激活选区中心所在的目标窗口，以单个滚轮刻度尝试向下滚动，并等待画面稳定，手动模式不注入滚轮。通过逐行特征定位重叠候选，再校验有效内容和接缝唯一性，避免留白、重复排版造成错误拼接；支持跳过配置的固定页眉 / 页脚。

`long-capture.cjs` 保存最后成功匹配的画面与长图。自动滚动无效或匹配失败时转为手动，控制面板提示在原选区内缓慢向下滚动，也可主动点击「手动滚动」。重复、回滚或无法对齐的画面不会追加，也不会替换匹配基准或占用帧数。用户点击完成或达到帧数 / 尺寸上限后生成结果。动态截图定时采集选区，在独立线程中编码 GIF，最多 300 帧，无声音。

## OCR / 翻译

请求由主进程发起。远程接口必须为 HTTPS；明确配置的 localhost、127.0.0.1 和 ::1 可使用 HTTP。不跟随重定向。

- OCR API：POST `{image_base64,mime_type:"image/png"}`。
- 翻译 API：POST `{text,source,target}`。
- JSON 返回字段支持点分隔路径，如 `data.text`、`translation`。
- AI：兼容 Chat Completions 的完整地址，发送 `{model,messages,stream:false}`；OCR 使用图像消息，翻译使用文本消息。
- API Key 放入 `Authorization: Bearer ...`，无鉴权本机接口可留空。

不内置第三方账号、模型、密钥或离线 OCR。其他厂商协议可通过自行部署的适配接口转换。
